# Northline

这是一个给「50 分钟内能讲清楚」准备的前端演示店：海外旅行向选购站，英文为主、中文为辅。你打开就能逛，不用起后端。

## 你演示时走哪条线

别铺开讲评价、推荐、账号。就走这条主路径就够了：

1. **找到商品** — 首页搜一下、筛分类/价格，点进详情  
2. **看规格** — 选颜色、改数量  
3. **进购物袋** — 改数量、换配送地区，看运费怎么变  
4. **演示确认** — 点「提交演示订单」，证明流程走完了；**不接支付 SDK**，也不收卡号

购物袋、配送地区、语言都存在浏览器 `localStorage` 里，刷新不会丢。换语言时规格用的是稳定 key（比如 `Sand`），购物车不会因为文案变了就对不上。

## 优化点（讲的时候按这个说）

时间就按 50 分钟来排，所以优化不是把功能堆满，是把能演示的那条路做稳，其余先不碰。

**只做主路径。** 找到商品、看规格、进购物袋、演示确认。评价、推荐、账号这三块演示用不上，做了反而容易讲散，所以没铺。

**数据全在前端。** 商品是写死的模拟数据，购物袋、配送地区、语言都塞进 `localStorage`。没有后端也能刷新、换语言、关了再开还在。代价是不能多人同步，演示一台电脑就够。

**结算停在演示确认。** 点下去会给一个演示订单号，然后清空购物袋，证明流程走完了。不接支付 SDK，也不收集卡号。现场不会卡在密钥、回调、测试卡上。

**样式自己用 Tailwind 排。** 没用商城模板。看起来是编辑向旅行品牌：英文为主，中文当辅助。页头、商品、购物袋是同一套字和颜色，不是套了一层现成皮肤再改。

**语言用稳定规格 key。** 购物车里存的是 `Sand` 这种 key，不是「沙色」这种显示文案。切到中文只是把显示换成「沙色」，购物车里还是同一条。文案要维护两份（`en.ts` / `zh.ts`），成本高一点，但换语言不会把已加购的规格弄丢、弄重。

**搜索框跟着地址走。** 搜过的词在 `?q=` 里。从详情返回、浏览器后退时，输入框会跟着当前地址更新，不会出现「列表已经按新词筛了，框里还停着旧词」。

**文案只留正在用的那一套。** 语言走 i18next。旁边曾经有一份没接上的旧文案，改的时候容易改错文件，已经删掉。

**部署做成加分，不当必做。** 构建和 `vercel.json` 都准备好了。时间不够就本地演示加录屏；有空再按下面的步骤丢到 Vercel。刷新商品页、购物袋不会 404，因为所有路径都会回到 `index.html`。

## 怎么在本机跑

```bash
npm install
npm run dev
```

浏览器打开 `http://localhost:8888`。要看生产包：

```bash
npm run build
npm run preview
```

## 时间紧怎么交差

**本地演示 + 录屏就够交差。** 按上面主路径点一遍，中英文各切一次，窄屏看一下手机底栏购物袋入口。

## 部署到 GitHub Pages

推到 `main` 后，GitHub Actions（`.github/workflows/pages.yml`）会构建并发布。

线上地址：https://qingcheng985.github.io/web-app-shop/

仓库只需确认一次：Settings → Pages → Build and deployment → Source 选 **GitHub Actions**。

构建时 `VITE_BASE=/web-app-shop/`，本地 `npm run dev` 仍然是站点根路径。详情页和购物袋刷新走 `public/404.html`：先记住所访问的地址，再回到首页，由应用把地址还原。

## 技术栈（给同学看的）

- React 19 + Vite + TypeScript  
- React Router  
- Tailwind CSS v4（`@tailwindcss/vite`）  
- i18next（`src/i18n/en.ts` / `zh.ts`）  
- Context + `useReducer` 管购物袋；`localStorage` 持久化  
- 商品在 `src/data/catalog.ts`，图用 Unsplash

## 已知坑

- 没网或 Unsplash 被拦时，商品图会空  
- 运费、关税只是演示文案，不是真实报价  
- GitHub Pages 没有服务端重写。深链刷新依赖 `public/404.html`，站点路径必须是 `/web-app-shop/`
